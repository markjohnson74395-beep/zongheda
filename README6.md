# 上午秒开、下午半分钟：纸飞机网页版加载慢怎么定位——用一张五段计时表把网络、浏览器、账号三面分开

同一台电脑，同一个浏览器，同一个地址。上午九点四十打开纸飞机网页版，两秒出二维码；下午三点再点开，地址栏那个圈转了二十八秒，页面才勉强立起来，头像还是一片灰，消息列表一格一格往下补，像有人在后台慢慢填。中间我没装软件，没改设置，也没换网络。

“同一台机器两副面孔”最容易被一句“网络抽风”打发掉。可它解释不了一件事：线路真坏了，它应该一直坏；线路真忙，旁边几个站也该一起慢。所以别急着换节点，先把这二十八秒拆开——它究竟花在哪一段。

## 一、慢和打不开是两套病，别拿一套药去治

打不开，指的是连接压根没建立起来：白屏、`ERR_NAME_NOT_RESOLVED`、`ERR_CONNECTION_RESET`。慢，指的是连接建起来了，每段都在拖：解析、握手、服务器响应、内容下载。

这两件事的处理顺序几乎是相反的。打不开要从入口查起；慢要从计时查起。我见过最常见的错误，是把“慢”当“打不开”治——换三条线路、重装浏览器、清十次缓存，全程没有测过一次“到底哪一段耗时”。站点上那份 [网页版访问与加载检查清单](https://tlgroq-web.com) 把访问、缓存、权限拆成独立条目，就是按“先定位再动手”这个思路切的。

## 二、把一次加载切成五段，用五个数字替掉“感觉很慢”

命令行跑一条就够，地址换成你要测的页面：

```
curl -o /dev/null -s -w "DNS:%{time_namelookup} TCP:%{time_connect} TLS:%{time_appconnect} TTFB:%{time_starttransfer} 总:%{time_total}\n" https://tlgroq-web.com
```

取基线用的一次请求就够，别套循环跑。五个数字的含义：“DNS”是解析耗时，“TCP”是握手完成，“TLS”是加密协商完成，“TTFB”是首个字节到达，“总”是全部收完。真正要看的不是绝对值，而是**两次数值之间哪一段变了**。

浏览器里还有一份更细的。`F12` 打开开发者工具 → 切到「网络」面板 → 勾上「停用缓存」→ 按 `Ctrl + F5` 硬刷新 → 点列表里第一条文档请求 → 看「计时」。它把一次请求拆成“已停滞”“等待服务器响应”“内容下载”几段。名字在不同版本里略有出入，位置没变，卡在哪一段一眼能看出来。

几组可用的参考线：

- 解析 50 毫秒以内、握手 150 毫秒以内（同城线路）、TLS 300 毫秒以内，这三段加起来不该超过半秒；
- 「等待服务器响应」超过 1 秒算异常，超过 3 秒基本可以判定出口侧有问题，而不是你的机器；
- 内容下载这一段，几百 KB 的页面不该超过 1 秒，拖着走十几秒的，通常是带宽被别的东西吃了。

## 三、定位表：三种“慢”的指纹长什么样

| 量出来的样子 | 更像哪一面 | 先动哪里 |
| --- | --- | --- |
| 解析就要 3 秒，握手迟迟不开始 | 网络·解析 | 换解析服务器，清本机 DNS 缓存 |
| 握手 200 毫秒很干净，TTFB 却要 6 秒 | 网络·出口拥塞 | 换线路，同一时段做对照 |
| TTFB 正常，内容下载拖十几秒、进度条一格格爬 | 网络·带宽被占 | 关后台同步、网盘、系统更新 |
| 骨架秒出，头像和消息一个个补，滚动还卡 | 浏览器·渲染 | 无痕窗口对照，逐个关扩展 |
| 换个号就快，只有你这个号慢 | 账号·会话数据量 | 清站点数据重建，关自动下载 |
| 请求都很快，但输入有延迟、滚动掉帧 | 浏览器·缩放与图形加速 | `Ctrl + 0` 复位，试开关硬件加速 |

对着六行看，“下午半分钟”会收敛到其中一行。

## 四、网络面：握手快、下载慢，跟“能不能打开”是两件事

网络面的慢有两种，处理方式正相反。

一种是**服务器没回**。握手几十毫秒就完成了，TLS 也顺利，然后就干等——TTFB 五六秒。这是出口或节点侧的问题，换线路是唯一有效的动作，刷新页面只会让等待重新排队。

另一种是**带宽被占**。TTFB 三百毫秒，很正常，但内容下载拖了二十秒，页面像在滴水。这时候换线路没用，因为瓶颈在你这一端：网盘在同步、系统在装更新、另一个标签页在播视频、手机在同一台路由器上备份相册。把上传下载的活停掉就回来了。

区分办法很土但有效：同一时间换手机热点打开同一页面。热点快，问题在你原来的出口或局域网；热点一样慢，问题在更上游，这时候换节点才有意义。WiFi 那一段也值得看一眼——五米之外隔一堵墙，2.4G 频段的实际吞吐能掉到原来的几分之一，信号栏只显示“已连接”。

## 五、浏览器面：三个藏起来的开关

先排除扩展。Chrome 地址栏输入 `chrome://extensions`，把广告拦截、脚本管理、翻译、比价、密码管理器逐个关掉——不用卸载，右边开关拨一下就行，关一个刷一次页面。更快的筛法是无痕窗口：无痕里正常，扩展的嫌疑基本坐实，因为无痕默认不加载扩展。

再查浏览器自己“省资源”的功能。Chrome 在 `chrome://settings/performance` 里有「内存节省程序」，标签页闲置久了会被冻结，切回来要重新加载——你以为网慢，其实是浏览器把页面卸载了。Edge 对应的是 `edge://settings/system` 里的「睡眠标签页」，默认在闲置一段时间后生效，关掉它，或者把站点加进“永不休眠”名单。

缩放和图形加速也会伪造“慢”。`Ctrl + 0` 复位到 100%，滚动卡顿会明显改善；「使用图形加速」这个开关值得拨两次对比，老显卡驱动开着它反而更花屏、更卡。

Safari 的坑不一样。它默认没有开发菜单，得先进「Safari → 设置 → 高级」，勾上「显示网页开发者功能」，才会出现「开发」菜单，能看每个请求的分段耗时。Firefox 则在「设置 → 常规 → 性能」里，取消勾选「使用推荐的性能设置」之后才会露出硬件加速选项。

版本差异记一笔：Chrome 111 之后，开发者工具把「计时」并进了请求详情，不再是独立标签，早期版本那块叫「Timing」。四个浏览器的开关位置和差异，站点上按 [Chrome、Edge、Safari、Firefox 分了四篇](https://tlgroq-web.com) 写，路径比这里更细。

## 六、账号面：只有你这个号慢，就别再查网络了

判断只要一句话：同一个浏览器、同一条线路，换个刚注册的小号登进去。小号两秒出页面、你这个号还是二十几秒，问题在账号侧。

账号侧慢通常三个来源：

- **会话太多**。几百个群和频道，首屏要拉未读计数、渲染会话列表，数据量几何级往上涨；
- **媒体自动下载**。网页版在「设置 → 数据和存储 → 自动下载媒体」里，按体积把图片、视频、文件关掉，首屏会轻很多；
- **本地库膨胀或损坏**。网页版把会话缓存在浏览器的 IndexedDB 里，长期不清会到一个很别扭的状态——打开就慢，滚动还卡。处理办法是清站点数据：`chrome://settings/content/all` 搜站点名，删掉它的存储，然后重新扫码。

清站点数据等于退出登录，共享电脑上做之前想清楚；清完第一次打开会慢，那是在重建本地库，第二次才是真实速度。

## 七、复测纪律：改一项，测一次

1. 关掉全部扩展，用无痕窗口测一次，记下秒数；
2. `Ctrl + 0` 复位缩放，同一页面再测一次；
3. 关掉「内存节省程序」或「睡眠标签页」，第三次；
4. 换手机热点做对照，分清是本机出口还是局域网；
5. 同一条线路换小号登录，测账号侧；
6. 清站点数据重建本地库，隔十分钟再测（第一次不算数）；
7. 把每次的五个数字抄进一张表，写上时间点和改了什么。

七步走完，“下午半分钟”基本会落在某一行上。上午快、下午慢的，多半在第 4 步和第 6 步露馅：要么共用出口在下午被占满，要么本地库一天下来攒了太多东西。

## 收口：留一份基线，下次不用从零猜

那台笔记本后来查到结果了。上午那次是解析 40 毫秒、握手 90 毫秒、TTFB 600 毫秒、总 1.9 秒；下午重测，TTFB 变成 6.8 秒——问题不在浏览器、不在账号，是同一条线路的出口在下午被同一栋楼的人占满了。切到手机热点，TTFB 回到 700 毫秒，页面两秒打开。

有了这份基线，下次再慢，我只需要跑一条命令，看是哪个数字变了，就知道该动哪里。这套“先量化、再动手”的顺序，以及各段耗时的中文对照，在 [tlgroq-web.com](https://tlgroq-web.com) 的浏览器排查条目里能逐项核。把它当体检表用，比一条条试错省事得多——尤其是那种上午好好的、下午突然变慢的毛病，它几乎不会给你第二次猜中的机会。

# 换掉三套 IP 还在整批被封：真正出卖你的是 6 个设备指纹与行为特征（附特征对照表与 7 步排查顺序）

前几天有人把账号表发到我这儿：二十个批发小号，七天换三套住宅 IP，落点分在三个城市，第三套上线的当晚，剩下十一个号四十分钟内全灭。他问我是不是买到了垃圾号。

我让他打开 Telegram 桌面端 Settings → Advanced → Active Sessions，把二十个号的会话详情截下来拼成一张图，二十张摆在一起，`device_model` 那一列全是同一个字符串，`system_version` 分毫不差，最近活跃时间全挤在晚上八点到九点五十。

问题不在 IP 上。IP 只回答"你在哪"，平台手上还捏着两列更硬的证据：你在用什么设备、你以什么节奏动。前一套换的是外套，后两套连脸都没换。

## **一、IP 是"你在哪"，指纹是"你是谁"**

很多人把风控想成一道闸，觉得过了就没事。它更像一张台账：每一列都能单独看，但真正决定命运的是列与列之间能不能对上。

IP 的麻烦在于它是可租的：住宅、机房段、代理池、移动网络，几十到几百块就能换一批。平台清楚这点，所以从不把 IP 当唯一判据，只当关联线索去和别的列交叉。

设备指纹不一样。它是客户端登录那一刻自报的家门：机型、系统版本、客户端版本、界面语言、系统语言。这些字段稳定、廉价、不随你换出口而变，一个人手上就那么几台设备。

行为特征最不客气，它不看技术数据，只看"你办事的方式"：几点上线、隔多久发一条、文案怎么开头、加群按什么顺序。投入最低，却最难伪装——它是习惯，不是配置。

所以"IP 脏了"只在掉单个号时成立。一批号同时掉还围着 IP 打转，力气就花在了最不重要的那一列。

## **二、六个特征摆在一起看，谁最致命**

| 特征维度 | 平台侧看到什么 | 换一次的成本 | 被识别的后果 | 能改到多干净 |
| --- | --- | --- | --- | --- |
| **IP 出口** | ASN、地理位置、是否机房段或代理池 | 低，几十到几百一条 | 同段聚类，整批进复核 | 中，换多了反而反常 |
| **设备指纹** | `device_model`、`system_version`、`app_version`、`lang_code` | 中，要真换环境不是换壳 | 一号多号共指纹，直接判同一人 | 低，重装客户端仍留痕 |
| **行为节奏** | 登录与发消息的时间分布、操作间隔 | 高，改的是习惯 | 提前进观察池，限制先于封禁 | 低，机械节奏最好抓 |
| **资料与文案** | 用户名格式、头像风格、简介、首条消息文本 | 低，但要花时间 | 模板化判批量，人工复核 | 中 |
| **社交图谱** | 加群顺序、共同群、谁拉谁 | 极高，要重排关系 | 掉一个带一片 | 低 |
| **下单批次** | 同批下单时间、同一支付通道 | 卖家侧决定 | 整批被标记为同源 | 你控不了 |

这张表按见过的案例排：设备指纹叠加行为特征，等于给号贴了同一张身份证；单一 IP 撞车反而最容易解释过去。

## **三、设备指纹：机型早就写进会话里了**

MTProto 建连的第一步有个 initConnection，客户端要把 `device_model`、`system_version`、`app_version`、`lang_code`、`system_lang_code` 一股脑报上去。这些字段不是被偷偷抓的，它们就摆在你自己的会话列表里，只是多数人从不点开。

几个具体表现：

- Telegram Desktop 的 tdata 目录里，`D877F783D5D3EF8C` 放着 `key_datas` 与 `settingss`，会话身份就在里面。整个目录拷到第二台机器，服务端眼里还是原来那台设备——不用验证码，指纹没变。
- 安卓模拟器里装三个客户端，`device_model` 往往还是被模拟的那个型号，三个号共用一套指纹。
- 网页版的 k 版本号、时区偏移、界面语言一旦和 IP 地理位置对不上，这一栏就格外扎眼。

有个现象很能说明问题：同一台机器短时间连登几个号，常见报错是 `Too many attempts, please try again later`；登进去动作稍快，就会撞上 `FLOOD_WAIT_` 后面跟一串秒数，或者给陌生人发消息直接吃一个 `PEER_FLOOD`。这三条都不是封号，是"你已经进了观察池"的信号。太多人在这一步继续换 IP 硬试，把观察期试成了封禁。

## **四、行为特征：最便宜，也最难伪装**

- **时间**。二十个号同一小时上线，平台看到的不是二十个用户，是一个人在二十个窗口来回切。
- **节奏**。人手点，间隔是散的：三百毫秒、两秒、十一秒；脚本点，间隔恒定。恒定本身就是签名。
- **文案**。同一段开场白发不同人，标点、emoji 习惯、换行方式一模一样，相似度一跑就出来。
- **关系**。二十个号在同一周进同一批群，谁拉谁、谁跟谁同群，这张图比任何单个字段更指向同一个操作者。
- **活性**。资料全空、从不打开频道、每天在线固定十二小时，凑一起比一个话多的小号更像机器。

限额的真实边界：免费号群组与频道上限 500 个（Premium 翻倍到 1000），但这数字跟新号没关系——新号一天加二三十个群就先吃一轮限制；给非联系人主动发消息，一天十几到二十条就逼近 `PEER_FLOOD`。管用的不是规则写的数，是风控愿意容忍的数。

## **五、掉号之后的 7 步排查顺序**

顺序是按"证据强弱"排的，别从 IP 开始查起。

1. **先看时间分布**。同批半小时内掉完是环境问题；七零八散地掉是单号质量或个体动作问题。这一步决定后面查哪一头。
2. **拉会话截图横向比**。把 `device_model`、`system_version`、`app_version` 三列并排，重复的圈出来。重复越多，问题越不在 IP。
3. **找"错配"**。同一个 IP 上冒出多个不同机型，或者同一个机型在三天里跨了三个城市，两种错配都指向环境没隔离干净。
4. **翻首登后 24 小时的动作**。加了多少群、私聊了多少人、发的是不是同一段文本。这决定新号会不会重蹈覆辙。
5. **找前置信号**。有没有出现过 `Too many attempts`、`FLOOD_WAIT_`、`PEER_FLOOD`。有，说明封禁前已经给过警告。
6. **查客户端之外的东西**。有没有拷过 tdata、有没有几个人共用一台机器或模拟器、有没有用同一个浏览器配置反复登。
7. **补台账**。设备标识、线路、时区、界面语言、首登时间写进同一张表。下一批按表错开，而不是凭印象错开。

## **六、"我明明换了 IP"：三种越换越像的做法**

- **同一台机器换城市**。上午东京、下午法兰克福、晚上洛杉矶，中间没有移动痕迹。真人做不到三小时跨两个洲，这种轨迹比不换更可疑。
- **IP 在境外，语言和时区在国内**。出口落在法兰克福，时区偏移是 +8，`lang_code` 是 zh-hans，系统语言 zh-CN。三项互相打架，比三项一致但全在国内更显眼。
- **换 IP 比换号还快**。一个号三天走五个出口，平台看到的是"这号在被人搬来搬去"，权重掉得比固定线路还快。

三种做法的共同点：动的都是最外层，真正被判定的那两列一动没动。
